pdfkit and puppeteer both produce untagged PDFs by default. An untagged PDF has no headings, no table structure and no reading order, so a screen reader announces the whole page as a single blob of text. Amounts drift away from their labels. Column headers disappear.

Your web app has axe-core in CI. Your PDFs have had nothing. This is that check.

Why this became urgent

Accessible documents
stopped being optional.

The European Accessibility Act has applied since 28 June 2025. It reaches customer facing documents such as invoices, statements, contracts and reports for a wide range of services sold into the EU. Each member state sets its own penalties and its own enforcement body.

The practical problem is not the law. It is that teams had no way to check. Web accessibility has had automated tooling for a decade. PDF accessibility had desktop software, paid services, and Java command line tools, none of which fit into a Node build.

This runs with npx. No installer, no licence, no Java.

  • 2001
    Tagged PDF arrives in PDF 1.4
    The structure tree has existed for over twenty years. Most generators still do not emit one.
  • 2012
    PDF/UA published as ISO 14289-1
    A precise definition of what an accessible PDF has to contain.
  • 28 June 2025
    European Accessibility Act applies
    Requirements reach customer facing documents, not just websites.
  • Today
    Your invoice pipeline has no check
    One line in CI closes it.
Thirteen checks

Every finding points at
a published clause.

Two profiles. recommended is what a team can reasonably fix this sprint. pdf-ua turns everything into an error. Any check can be turned off on its own.

CheckDefaultClauseWhat it catches
struct-treeerrorPDF/UA 7.1 · WCAG 1.3.1No tag tree at all. The one that matters most.
document-langerrorWCAG 3.1.1Missing or malformed /Lang, so the reader guesses the language
figure-alterrorPDF/UA 7.3 · WCAG 1.1.1Figure with no alt text, or alt text like image or chart.png
table-headerserrorPDF/UA 7.5 · WCAG 1.3.1Table with data cells but no header cells, so values lose their column
form-field-labelerrorPDF/UA 7.18.4Form field with no /TU tooltip, which is its accessible name
marked-contentwarnPDF/UA 7.1MarkInfo/Marked not set to true
document-titlewarnWCAG 2.4.2No title, or a title viewers will not display
untagged-imagewarnWCAG 1.1.1More images on the page than Figure elements in the tree
heading-orderwarnWCAG 1.3.1Heading levels skip, or the document does not start at H1
link-altwarnPDF/UA 7.18.5Link annotation with no description of where it goes
tab-orderwarnPDF/UA 7.18.3Page has annotations but no /Tabs /S, so keyboard order is arbitrary
parent-treewarnPDF/UA 7.1Tagged document with no /ParentTree to map content back to its tags
extraction-allowedwarnPDF/UA 7.1Encryption permission flags that block assistive technology from reading anything
Beyond pass and fail

It also tells you what your generator is really emitting.

Every report carries a facts object, including a count of every structure tag in the document. This is usually the most useful part. Authors are often surprised to learn their template produces two hundred paragraphs and not a single heading. 

{
  "pages": 4,
  "tagged": true,
  "lang": "vi",
  "title": "Hóa đơn 2026-0142",
  "images": 3,
  "figures": 1,          // two images never made it into the tree
  "tags": { "P": 212, "Table": 2, "TD": 48, "Figure": 1 }
}                              // no H1, no TH: the structure is flat
Three ways to run it

Check the file, the folder,
or the buffer.

One

On a file you already have

Point it at a PDF or a folder of them. Exit code is 1 when there is an error, so it works as a gate anywhere you can run a command.

npx pdf-a11y invoice.pdf

npx pdf-a11y ./out --profile pdf-ua
Two ★

In CI, on what you ship

Generate the PDFs your service actually sends, then check those. The github format puts each finding on the pull request.

- run: node scripts/invoices.js
- run: npx pdf-a11y ./out \
    --format github
Three

Before it touches disk

checkPdf takes a Uint8Array, so a puppeteer buffer can be checked in the same function that made it. Read errors come back on the result instead of throwing.

const bytes = await page.pdf();
const report = await checkPdf(bytes);

if (report.errorCount > 0) {
  throw new Error("not accessible");
}
What it cannot do

A checker is only trustworthy
if it says where it stops.

No automated tool can certify a PDF as accessible, and any tool that claims otherwise is selling you something. These are the edges, stated plainly.

Reading order

It can tell you an order exists. It cannot tell you the order makes sense. A tag tree in the wrong sequence still passes.

Alt text quality

It catches the mechanical failures: empty, whitespace, a file name, or a placeholder word. Whether a real sentence describes the image well needs a person.

Colour contrast

Out of scope. Contrast needs the rendered page, and this reads the object graph.

Repair

It reports, it does not rewrite. Fixing means changing the generator, which is where the structure has to come from anyway.
